# 低资源平台「利用 CPU 特性」运行时性能优化

## 前提（诚实说明，避免误解）
Go 标准库 `crypto/sha256` / `crypto/aes` 在 **arm64 上已自动走 SHA-2/AES 硬件指令**（`internal/cpu` 运行期探测 `HasSHA2`/`HasAES`），`pbkdf2`、AES-GCM 白嫖加速；**无需手写汇编/微码**。
MIPS（含 softfloat）无硬件 crypto，纯整数软件实现；softfloat 只影响浮点，对整数哈希无额外惩罚。
因此本计划不写汇编，而是：确保构建拿到硬件加速架构 + 用 Go 的「平台感知」运行时机制（GOMEMLIMIT）+ 按架构调 CPU 密集默认值 + 移除惩罚慢核的阻塞/正则开销。
**功能一个不少**（已与用户确认）：不引入 `-tags minimal` 阉割 Vault/Redis；MIPS 上 SQLite 不可用是 upstream 约束（`accounts_sqlite.go`/`accounts_nosqlite.go` 已自动剔除），维持现状。

## 1. GOMEMLIMIT：平台内存感知 GC 硬上限（最高价值，新增）
- 在 `loadtuner.go` 的 `newLoadTuner()` 中增加 `debug.SetMemoryLimit(...)`：按设备物理内存（`totalMem()` 已由 sysinfo 提供）留 5–10% 余量设软上限（如 64MB 设备设 ~48MiB）。
- 价值：项目当前 `loadtuner.go:102` 启动即 `SetGCPercent(-1)`（GC 关），首轮状态切换前（最多 ~15s）无 GC 兜底；GOMEMLIMIT 是**唯一**在 GOGC=off 时仍生效的 GC 控制，可在此空窗期防堆爆炸→OOM。
- 嵌入式档位（自动检测 `NumCPU<=2 || 总内存<=512MB`，新增 `embedded.go`）下更激进：在 GOGC 三态机之外叠加该硬上限；非嵌入式保持默认（不设或设很大）。
- 新增显式开关 `-low-resource`（`*bool`）强制开/关预设；未设则按自动检测。
- 通过 `GET /api/load` 一并暴露当前 memoryLimit 值，便于排查。

## 2. 构建矩阵 arm64 优先（拿到硬件 crypto）
- `.github/workflows/ci.yml` / `release.yml` 不动架构列表（已含 Android/OpenHarmony arm64/arm、MIPS softfloat），但确认：
  - Termux/OpenHarmony/现代开发板一律产出 **linux/arm64** 主构建（白嫖 SHA/AES 硬件加速）。
  - `linux/arm GOARM=7` 仅用于 32 位 OpenHarmony/老 ARMv7；MIPS 保持 `GOMIPS=softfloat`（路由器无 FPU，错设会 illegal instruction）。
- 不做功能裁剪，仅明确优先级与注释。

## 3. 按架构调 PBKDF2 默认迭代（利用 CPU crypto 差异）
- `vault_crypto.go:40` `defaultPBKDF2Iterations=600000` 维持 arm64 默认。
- 自动检测：MIPS / armv7（无硬件 SHA）设备，启动时把 Vault 默认下限/推荐默认降到安全值（如 100000），避免数秒级解锁延迟（`vault_handlers.go:491` unlock 等调用点已用 `v.vault.pbkdf2Iterations`）。
- 仍完全可配置（`-vault-pbkdf2-iterations`，main.go:49），仅调整"默认值"来源，不改强制下限语义。

## 4. 移除 overview 的 800ms 阻塞睡眠（减负慢速顺序核）
- `overview.go:21` `netRates()`（300ms 睡）、`:31` `cpuUsage()`（500ms 睡）改为：
  - 网络速率复用已有后台采样器 `cachedNetRates()`（instance_stats.go:213，2s 周期）。
  - CPU 占用改用 `processCPUUsage()`（runtime/metrics，无睡眠）或缩短采样窗口（500ms→200ms）。
- 效果：每个 `GET /api/overview` 从阻塞 ~800ms 降到近零；仪表盘轮询不再占用慢核。非嵌入式档位行为不变。

## 5. `parseServerLine` 正则前置廉价守门（instance_stats.go:40）
- 当前每行输出跑 4 个回溯正则（rePlayersVanilla/Simple、reTPSTriple/Simple）。
- 在跑正则前用 `strings` 前缀/子串快速排除绝大多数无关行（如先 `strings.Contains` 命中 "players"/"TPS" 才跑对应正则），避免对每条 MC 日志行做 4 次正则回溯。慢核上稳态 CPU 显著下降。

## 6. `/proc` 解析后台缓存（sysinfo_linux.go）
- `osMem`（`/proc/meminfo`）、`netCounters`（`/proc/net/dev`）、`cpuJiffies`（`/proc/stat`）目前每次调用都 `ReadFile`+`Split`+`ParseUint`，无缓存。
- 新增短 TTL（1–2s）后台采样 + 缓存，复用 `cachedNetRates` 的同款模式；overview/实例指标读取走缓存，减少慢核的 syscall 与字符串解析开销。解析函数语义不变。

## 7. 每实例内存上限自适应（配合前述嵌入式档位）
- 嵌入式档位下：`NewLogBuffer` 默认 2MB→512KB（process.go:346）、`newLogLines` 1000→300（process.go:365）、`metricsRingSize` 60→30（instance_metrics.go:32）。
- 全部提升为可配置项（`-log-buffer-kb`、`-log-lines`），加入 `nodeOptions`/`Config`/`applyConfig`（config.go），`config.example.json` 补注释。
