# 等保二级自查表（GB/T 22239-2019 第二级）

- 适用对象：IriX Node 本地节点守护进程（含加密保险库 Vault 功能，`docs/vault-design.md`）
- 说明：本表覆盖**技术控制项**中软件可实现的部分；非技术项（管理制度、物理环境、
  人员、运维）由部署方配合有资质的测评机构完成，不在软件范围内（见 §3）。
- 达标流程：定级备案 → 差距整改 → 测评机构现场测评。软件能力只支撑技术面，
  「达到等保二级」以测评机构出具的测评报告为准。

## 1. 部署前提（软件侧红线）

| 前提 | 说明 |
| --- | --- |
| TLS 开启 | `-tls-mode auto`（自签）或 `manual`（正式证书）；`-vault` 强制要求 TLS，否则拒绝启动。等保部署必须开启（远程管理传输保密） |
| NTP 时钟同步 | TOTP 依赖服务器时钟准确（偏差 >±30s 将导致解锁失败） |
| 密码策略 | 保险库账号密码默认 ≥12 位且含大小写+数字，90 天更换（`-vault-password-expire-days`，可配 `-vault-force-expire` 强制） |
| 审计落盘 | `-audit-log` 保持默认开启；审计轮转归档到 `{data}/backup/audit/`（防覆盖丢失） |
| 备份 | 定期 `POST /api/vault/backup` 导出加密备份包；恢复令牌物理保管（丢失 = 数据不可恢复） |
| 监听范围 | 建议仅监听 127.0.0.1；局域网访问设置强 `-apikey` 并配合防火墙 |
| 运行时权限收敛（OpenBSD） | OpenBSD 部署启用进程自限制：`pledge` 收敛 syscall 到最小集（inet/dns/rpath/wpath/cpath/flock/unix/proc/exec 等）、`unveil` 锁定文件系统可见范围为数据目录 + 系统二进制目录；其他平台无 pledge/unveil，依赖部署侧降权与 systemd 加固 |

## 2. 技术控制项自查

| 控制项 | 要求摘要（二级） | 软件落地 | 状态 |
| --- | --- | --- | --- |
| 身份鉴别 | 身份标识唯一、鉴别信息复杂度、定期更换 | 唯一用户名 + 密码复杂度校验 + 90 天更换策略（到期提示/强制） | ✅ |
| 身份鉴别 | 登录失败处理（限制非法登录次数） | unlock/recovery/初始化验证统一限速（用户+IP 双维度，默认 5 次/15 分钟锁定） | ✅ |
| 身份鉴别 | 远程管理防窃听 | TLS（默认关闭、用户显式开启；vault 强制） | ✅ 部署前提 |
| 身份鉴别（超额） | 双因素（三级要求，二级超额实现） | TOTP（密码技术）+ 密码 + 证书签名三重认证 | ⭐ 超额 |
| 访问控制 | 最小权限、文件级粒度 | 未解锁数据面 403；按需解密；文件操作限定实例 cwd（`NormalizePath`） | ✅ |
| 安全审计 | 覆盖每个用户、重要安全事件、记录保护与备份 | 每请求审计（时间/IP/方法/路径/状态码/耗时/请求体，apikey 与保险库敏感字段打码）；vault 事件（解锁/锁定/改密/恢复/限速/迁移/孤儿回收）；轮转归档防覆盖 | ✅ |
| 数据完整性 | 传输+存储完整性 | TLS（传输）；AES-256-GCM 认证加密（存储，篡改即解密失败） | ✅ |
| 数据保密性 | 传输+存储保密 | TLS；instances.json 与 vaultFiles 实例文件区 GCM 密文存储，文件名/大小/时间不泄露（加密索引） | ✅ |
| 数据备份恢复 | 重要数据备份与恢复 | 加密备份包导出/恢复（恢复令牌 + 密码路径）；迁移幂等标记 | ✅ |
| 剩余信息保护 | 敏感数据释放后保护 | 会话密钥仅内存、锁定/超时清零（best-effort）；明文删除无法物理清除（介质残留如实披露） | ⚠️ 部分符合（best-effort） |

## 3. 非技术项（部署方责任，测评机构确认）

- **安全管理制度**：运维/操作/保密制度、安全培训、第三方人员管理。
- **安全管理机构**：岗位设置、人员配备、授权审批。
- **安全管理人员**：人员录用/离岗、安全意识培训、外部人员访问管理。
- **安全建设管理**：定级备案、方案评审、测试验收、供应商管理、等级测评整改。
- **安全运维管理**：环境/资产管理、监控与审计管理、备份恢复管理、应急预案。
- **物理与环境安全**：机房/设备/介质安全（物理控制项，软件不可覆盖）。

## 4. 残余风险与表述口径（测评沟通用）

| 项 | 口径 |
| --- | --- |
| 解锁会话期间节点进程被攻破 | 架构 A 固有残余风险：会话内主密钥在内存。缓解：空闲超时（默认 30 分钟）、手动锁定、审计留痕；彻底消除需客户端解密架构（B），不在本期 |
| 离线暴力破解密码 | 密码强度 = 离线安全上限；缓解：PBKDF2 600k 迭代 + 复杂度策略；二期增强：masterKey 额外用证书公钥包裹 |
| 剩余信息保护 | Go 运行时无法保证物理擦除（GC/swap）；实现为显式清零 + 锁定销毁（best-effort），自查按「部分符合」表述并附本说明 |
| vaultFiles 实例运行期明文窗口 | 物化实例运行期间工作目录为明文（进程必须直读文件）；崩溃残留由下次解锁回收；静态加密承诺不覆盖运行窗口 |
| 国密算法 | 二级不强制密评，AES 系列可接受；若测评提出国密要求（通常三级+密评），需按 `docs/vault-design.md` §12 的国密改造路线执行 |
